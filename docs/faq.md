# 常见问题与排障

按「现象 → 原因 → 处理」组织。想先了解功能与界面，请看 [用户指南](./user-guide.md)。

---

## 数据与配置

### 关掉程序后任务列表就空了，能保存任务吗？

不能。当前版本**不做任何持久化**：任务列表、右栏的「运行设置」与「新任务默认参数」
都只存在于内存中，关闭程序即丢失。已经复制到磁盘上的文件与 `logs/` 里的日志不受影响。

处理方式：把任务配置写在记事本里，或每次启动后重新新建（`Ctrl+N`）。
若希望长期保存，请把需求提给维护者（程序目前没有配置文件与自动保存机制）。

### 为什么右栏和「⚙ 设置」按钮不见了？

界面会随窗口宽度自动取舍：

- 窗口宽度 < 1040px → 隐藏整个右栏（运行设置、新任务默认参数不可见）；
- 窗口宽度 < 1120px → 隐藏「⚙ 设置」按钮。

把窗口拉宽即可恢复。窗口最小宽度为 1000px，因此最小化到最窄时这些区域一定不可见。

### 界面显示「v2.0（Rust + Tauri 重构版）」，但安装包属性里是 0.1.0？

这是已知的版本号不一致：设置面板的文案是产品代号，打包配置里的版本是 `0.1.0`。
以安装包/可执行文件的版本信息为准。

## 按钮为什么点不动

| 现象 | 原因 |
|---|---|
| `▶ 开始全部` 置灰 | 引擎正在运行，或任务列表为空（至少需要一个任务） |
| `■ 停止全部` 置灰 | 引擎没有在运行（「待执行」不代表在跑） |
| 卡片 `编辑` 置灰（提示「运行中不可编辑」） | 引擎运行期间不允许改任务配置 |
| 卡片 `删除` 置灰 | 引擎运行中；另外引擎层只允许删除**终态**任务（已完成/已停止/失败） |
| 卡片 `重跑` 置灰 | 任务不是终态，或引擎正在运行 |
| 卡片 `日志` 置灰 | 该任务还没有日志文件（从未执行过，或日志创建失败） |
| `校验目标盘空间` 置灰 | 目标目录还没填 |

## 路径与落盘位置

### 源选的是目录，为什么文件没有直接进目标目录？

这是设计行为：**目录源会整体复制到目标目录下并新建同名子目录**。

```
D:\照片\2024  →  E:\备份  ⇒  实际写入  E:\备份\2024\
```

任务编辑器在路径下方会即时提示「目录将整体复制到：`E:\备份\2024`」，保存前请对照确认。
如果只想要**单个文件**直接落进目标目录，请用「浏览文件…」把源选成那个文件：
此时文件名不变，直接复制进目标目录。

### 提示「目标目录位于源目录内部，会导致自我递归复制，已阻止」怎么办？

例如源 `D:\照片`、目标 `D:\照片\备份`：robocopy 会把已经写进目标的文件再当作源继续复制，
形成无限递归。请把目标改到源之外的路径（换盘、换目录层级）。

### 提示「源位于目标目录内部，可能造成数据覆盖，已阻止」怎么办？

把源放到目标之外的位置。若确实要做「源与目标互相包含」的同步，本工具会直接拒绝，
请改用专门的同步工具。

### 提示「源路径不存在（既不是文件夹也不是文件）」怎么办？

检查拼写、盘符是否存在、外接盘/网络盘是否已连接；UNC 路径（`\\server\share\…`）需要当前
用户具备访问权限。路径中的 `/` 会被自动规范化为 `\`。

### 长路径（超过 260 字符）或网络共享能用吗？

可以。程序会自动为超长路径加 `\\?\` 前缀（UNC 加 `\\?\UNC\`），命令行预览里能看到。
需要注意：命令预览中的 `\\?\` 形式是给 robocopy 用的，直接粘贴到资源管理器地址栏可能不友好。

## 复制过程

### 为什么进度条长时间停在 0% 或涨得比资源管理器慢？

进度不是 robocopy 自己报的，而是程序按固定间隔（右栏「进度刷新」，默认 1 秒）扫描目标端
推算出来的，且**只有文件大小与源完全一致才计入完成**（防止把写了一半的文件算成已完成）。
因此：

- 单个大文件复制期间，进度会长时间不变，完成后一次性跳变；
- 为了不拖慢复制，轮询只扫描源清单涉及的子树，并按「热点优先 + 预算轮转」的方式分摊，
  刚创建的深层目录可能比实际写入滞后一两轮；
- 把「进度刷新」调小（0.5 秒）会更实时，但会增加少量磁盘 IO。

进度收敛到 100% 后任务还要经过校验阶段，属正常。

### 为什么速度显示 `-- /s`？

速度只在有实际写入时才有采样值。任务处于扫描、校验、暂停写盘或已结束时会显示 `-- /s`。

### 可以同时跑几个任务？机械硬盘会不会更慢？

右栏「并行任务数」可选 1..8（默认 1，即先进先出逐个执行）。每个任务内部还有 `/MT` 多线程，
所以「并行任务数 × 线程数」才是总的并发度。机械硬盘建议并行不超过 2，
否则磁头来回寻道会明显变慢；SSD/NVMe 可以适当提高。

### 「断点重启 /Z」什么时候该开？

网络共享、移动硬盘等容易中断的场景建议打开：它会在中断处续传而不从头重来，
但速度会明显下降。本地稳定盘不要开。

### 为什么停止后目标目录里出现了不完整文件？

「停止」会立即终止 robocopy 进程，正在写入的文件就会被截断。
重新用「重跑」执行即可——目标端已是最新的文件会被跳过，只有不完整的部分会被重写。

### 有文件被占用/拒绝访问时程序会一直卡住吗？

不会。命令行固定使用 `/R:1 /W:1`（重试 1 次、等待 1 秒），失败后放弃该文件并继续，
避免单个坏文件卡死整批任务；该文件会体现在退出码（≥ 8，任务判为失败）与日志中。

### 试运行结束后为什么没有校验结果？

试运行 `/L` 只列出将要复制的文件、不写入任何数据，因此程序在试运行结束后直接判定完成
（阶段文本「试运行完成（未写入任何文件）」），不会进入复制后校验阶段。

## 校验

### 校验失败了，具体是哪些文件不一致？

界面只在任务卡片上显示汇总（`校验 通过数/已校验数`）与错误行
`校验未通过：x/N 个文件不一致`。**明细在任务的日志文件里**：点卡片「日志」查看尾部，
或直接打开 `logs/` 目录看完整文件；日志中最多列出前 10 条差异。

差异记录的原文格式为：

- `无法读取目标文件（<系统错误>）`
- `大小不一致：目标 <n> / 源 <m>`
- `修改时间不一致`
- `<算法> 哈希不一致`
- `读取失败（<系统错误>）`

引擎内部最多保留 500 条差异记录，超出部分只计入数量。

### 明明复制成功了，为什么快速校验报「修改时间不一致」？

快速校验比对「大小 + 修改时间」，并带 **2 秒容差**（适配 FAT/exFAT 只有 2 秒时间戳精度）。
如果仍报不一致，常见原因：目标文件被其他程序改写过、源文件在复制过程中被修改、
或目标盘文件系统的时间精度/时区处理不同。需要更强保证时请改用「哈希校验」。

### 哈希校验很慢正常吗？

正常。严格校验要读取源与目标各一遍内容，会与磁盘 IO 争抢。程序做了这些优化：
按 1MB 分块流式读取（不把大文件整体读进内存）、固定 4 个线程并发（上限 8）、
校验只在复制结束后进行。
对超大目录可先用「大小+时间戳」，需要时再对关键任务单独开哈希。

### 三种校验级别怎么选？

| 场景 | 建议 |
|---|---|
| 速度优先、robocopy 自身已校验过一遍 | 不校验 |
| 常规备份（绝大多数场景） | 大小+时间戳 |
| 关键数据、跨文件系统、需要内容级保证 | 哈希校验（SHA256 最严格） |

## 日志

### 日志控制台的行数怎么少了？提示「已裁剪 N 行」

这是性能护栏：界面只在内存中保留最近 2000 行日志，超限时按 400 行步长丢弃最旧的行，
面板最多渲染最后 800 行。**完整日志始终落盘**，需要全量记录请打开 `logs/` 里的日志文件。

### 日志里的中文会乱码吗？

不会。程序按系统控制台代码页（如简体中文 936、繁体 950、日文 932 等）解码 robocopy 输出，
日志文件以 UTF-8 写入并逐 8KB 增量解码，避免截断多字节汉字。

### 点「🗀 日志目录」没反应？

该按钮用资源管理器打开工作目录下的 `logs/`；若该目录尚不存在或已被删除，打开会静默失败。
随便跑一个任务（或手动在程序目录下新建 `logs` 文件夹）后再试即可。

### 日志能导出或分享吗？

界面没有导出按钮。日志本身就是普通文本文件，直接到 `logs/` 目录复制即可
（查看器只显示尾部约 32KB，完整内容在文件里）。

## 报错与异常

### 提示「未找到 robocopy.exe：本工具依赖 Windows 系统自带的 robocopy」

程序会到 `<SystemRoot>\System32\Robocopy.exe` 查找。若报此错，说明该文件缺失或被安全软件移除；
请在系统盘对应位置恢复 Robocopy.exe，或换一台正常的 Windows 机器。

### 任务失败，错误信息怎么写进日志查？

排查顺序建议：

1. 看卡片第 3 行的红色错误信息与退出码说明（对照[退出码对照表](./user-guide.md#11-退出码对照表)）；
2. 打开该任务的日志，搜索 `错误`、`ERROR`、`拒绝访问`、`未能`、`无法` 等关键字；
3. 退出码 16 表示 robocopy 未能正常启动或参数非法，通常是权限/路径问题；
4. 退出码 8 表示有文件无法复制，多为被占用、权限不足、磁盘满或路径过长；
5. 若错误是 `校验未通过：…`，按上文「校验」一节的处理方式排查。

### 界面卡顿怎么办？

先看日志控制台是否在高速刷行（`已裁剪 N 行` 增长很快），可先「收起」日志面板；
也可把「进度刷新」调大到 2~3 秒、并行任务数降为 1。若仍卡顿，请把日志文件与复现步骤反馈给维护者。

### 程序退出了，运行中的任务会怎样？

关闭窗口会终止所有运行中的 robocopy 子进程并等待调度线程退出，
目标端可能留下不完整文件——重新运行该任务即可（已完整的最新文件会被跳过）。
因此请避免在有重要任务运行时直接关窗。
